# Finance Bot

Telegram-бот для учёта личных финансов. Пишешь «кофе 5», бот сам предлагает категорию (по истории или с помощью ИИ), записывает расход и показывает остаток на счёте. Доход пишется с плюсом: «+500 зарплата». Есть несколько счетов, переводы между ними, история и статистика за месяц.

## Возможности

- Несколько счетов: 💳 карта, 💵 наличные, 🪙 криптовалюта; переключение активного счёта
- Валюты: USD, EUR, RUB, BYN
- Запись одним сообщением: `кофе 5` или `5 кофе`. По умолчанию — расход за сегодня
- Доход со знаком плюс: `+500 зарплата` или `зарплата +500`
- Дата прямо в тексте: `вчера кофе 5`, `кофе 5 позавчера`, `кофе 5 05.11` или `кофе 5 05.11.2026`. Токен считается датой, только если без него остаётся нормальная запись, поэтому `такси 12.5` остаётся суммой, а не 12 мая. Будущие даты не принимаются
- Категория угадывается по истории: если пользователь уже записывал «кофе» в «Еду», бот предложит её сам (регистр и пробелы не важны, учитываются все счета пользователя). Если не угадал, предлагает выбрать
- Если по истории не угадать, категорию предлагает ИИ ([Groq](https://console.groq.com), модель `openai/gpt-oss-20b`). В окне подтверждения такая категория помечена «🤖 предложил ИИ, проверь её», и её можно сменить. Нужен бесплатный ключ `GROQ_API_KEY`; без него бот работает как раньше, просто без ИИ
- Окно подтверждения со всеми данными (сумма, категория, счёт, дата) и кнопками «✅ Подтвердить», «📅 Сменить дату», «🏷 Сменить категорию», «❌ Отмена». Дата: «Вчера», «Сегодня» или `дд.мм.гггг` (будущие даты не принимаются)
- После подтверждения видны счёт и остаток, а под сообщением кнопки «✏️ Изменить» и «🗑 Удалить». «Изменить» открывает карточку операции: сумму, описание, дату и категорию можно поправить, не удаляя запись. При смене суммы баланс счёта двигается на разницу, а если денег для новой суммы не хватает (наличные и крипта), правка отклоняется. Та же карточка открывается из `/history`
- Переводы между своими счетами одной валюты с подтверждением; повторное нажатие «Да» не выполнит перевод дважды
- Баланс наличных и крипты не может уйти в минус; карта может (овердрафт), бот предупреждает об этом
- Готовые категории и свои категории с эмодзи; дубли вроде «Еда» и «🍔 Еда» не создаются
- Статистика за месяц, неделю или сегодня по всем счетам (каждая валюта отдельным блоком): расходы по категориям с долями в процентах, доходы, разница и сравнение с прошлым периодом. Текущий период сравнивается с тем же числом дней прошлого, а не со всем прошлым месяцем
- `/accounts` показывает общий баланс по каждой валюте, если счетов больше одного
- Лимиты на категории (`/limits`): месячный лимит в валюте активного счёта. После траты бот предупреждает, когда набралось 80% (один раз) и когда лимит превышен (после каждой траты сверх лимита). Считаются все счета этой валюты
- Регулярные операции (`/recurring`): зарплата, стипендия, подписки. Диалог: тип, категория, название и сумма, период и дата. Периоды: **каждый месяц** (в выбранное число, для 29-31 в коротких месяцах берётся последний день), **каждые N дней** (для сервисов, которые списывают «раз в 30 дней»: месяцы разной длины, и дата каждый раз уезжает ровно на N дней; N = 7 это раз в неделю) и **раз в год** (29 февраля в невисокосный год превращается в 28-е). В 20:00 в день платежа бот спрашивает «Добавить?» с кнопками «Добавить» и «Пропустить» и сам ничего не записывает без подтверждения. Следующая дата считается от запланированной, а не от дня нажатия. Из списка подписку можно открыть и поправить сумму (действует на будущие платежи) или ближайшую дату платежа
- История операций с постраничным просмотром (по 10 записей) и удалением с подтверждением
- Быстрый ввод без подтверждения, вечернее сообщение в 20:00 и итог недели по воскресеньям (подробнее в разделах ниже, настраивается в `/settings`)
- Проверка введённой суммы: запятая, ноль, отрицательные, слишком большие и `nan`/`inf`
- `/help` с подсказками и ответ на неизвестные команды

### Надёжность и безопасность

- Проверка остатка и изменение баланса выполняются одним `UPDATE` в базе, поэтому параллельные операции не потратят одни и те же деньги
- Дополнительно в таблице `accounts` есть `CHECK`-ограничение: даже в обход кода база не сохранит минус на наличных или крипте
- Данным из кнопок не доверяем: счёт и категория всегда проверяются на владельца
- Текст, введённый пользователем, экранируется перед выводом, поэтому символы вроде `<` и `&` не ломают сообщения
- Ответу ИИ не доверяем: подходит только id категории из списка, который мы отправили (и только категории этого пользователя нужного типа); ошибка, таймаут (4 с) или неуверенность модели просто показывают обычный выбор категории. Бот не падает, если Groq недоступен
- Стикеры и фото вместо текста в диалогах не ломают бота
- Отмена любого действия через `/cancel` или кнопку «Отмена»

## Команды бота

| Команда | Что делает |
|---|---|
| `кофе 5` | Записать расход |
| `+500 зарплата` | Записать доход |
| `/history` | Последние операции с листанием и удалением |
| `вчера кофе 5` | Записать расход задним числом (`позавчера`, `05.11`, `05.11.2026` тоже работают) |
| `/stats` | Расходы по категориям с долями, доходы, разница и сравнение с прошлым месяцем |
| `/stats неделя`, `/stats сегодня` | То же за текущую неделю или за сегодня |
| `/stats мм.гггг` | То же за конкретный месяц, например `/stats 09.2026` |
| `/limits` | Лимиты на категории: прогресс за месяц, добавление и удаление |
| `/recurring` | Регулярные операции (месяц, каждые N дней, год): добавление, правка суммы и даты, удаление |
| `/accounts` | Счета, общий баланс по валютам и переключение активного счёта |
| `/transfer` | Перевод с активного счёта на другой своей валюты |
| `/add_category` | Добавить свою категорию |
| `/create_account` | Создать новый счёт |
| `/help` | Как пользоваться ботом |
| `/settings` | Быстрый ввод без подтверждения и вечернее напоминание в 20:00 |
| `/feedback` | Написать автору отзыв, идею или сообщить об ошибке (можно анонимно) |
| `/delete_my_data` | Удалить все свои данные (счета, операции, переводы, свои категории, профиль) после подтверждения |
| `/cancel` | Отменить текущее действие |
| `/start` | Регистрация: выбор валюты и автоматическое создание счёта «Карта» |
| `/funnel` | Воронка регистраций за 14 дней. Только для автора (чат `ADMIN_CHAT_ID`), в меню команд не показывается |

### Как удалить операцию

1. Открой `/history` — у каждой записи есть номер и кнопка `🗑`.
2. Нажми `🗑` нужного номера — бот покажет операцию и спросит подтверждение.
3. «✅ Да, удалить» удаляет запись и возвращает тебя на ту же страницу истории, «Отмена» — просто возвращает.

## Стек

## Запуск

Два варианта: всё в Docker (так бот работает на сервере) или локально для разработки.

### Всё в Docker

```
git clone <адрес-репозитория>
cd finance-app
```

Создай `.env` по образцу `.env.example` (минимум `BOT_TOKEN` и `DB_PASSWORD`) и запусти базу и бота:

```
docker compose up -d --build
```

Миграции применяются сами при старте контейнера бота (`alembic upgrade head` в `Dockerfile`), а `DB_HOST` внутри Compose всегда `db`. Стандартные категории нужно заполнить один раз на новой базе:

```
docker compose exec bot python -m scripts.seed_categories
```

Обновление: `git pull && docker compose up -d --build`. Логи бота: `docker compose logs -f bot`.

Если подсказка категории ИИ всё время отваливается по таймауту, а в логах видно `_resolve_host` или `Temporary failure in name resolution`, контейнер не может найти адрес `api.groq.com`. Так бывает, когда на сервере стоит Tailscale или VPN: Docker передаёт контейнеру их DNS, который изнутри недоступен. Помогает явный DNS для сервиса `bot` в `docker-compose.yml`:

```yaml
    dns:
      - 1.1.1.1
```

Проверить из контейнера: `docker compose exec bot python -c "import socket; print(socket.getaddrinfo('api.groq.com', 443)[:1])"`.

### Резервные копии

Скрипт `scripts/backup.sh` делает дамп базы в `~/backups` (сжатый `.sql.gz`) и удаляет дампы старше 14 дней. Это число должно совпадать с `BACKUP_RETENTION_DAYS` в `app/constants.py`: бот называет этот срок пользователю при `/delete_my_data`. Если поменяете одно, поменяйте и другое.

Ручной запуск и проверка:

```
bash scripts/backup.sh
ls -lh ~/backups
```

Каждый день в 3:00 через `crontab -e` (путь к проекту подставьте свой):

```
0 3 * * * /bin/bash /root/finance-app/scripts/backup.sh >> /root/backup.log 2>&1
```

Бэкап, который ни разу не восстанавливали, ничего не гарантирует. Проверка на временной базе, рабочая не затрагивается:

```
docker compose exec -T db psql -U postgres -c "CREATE DATABASE restore_test;"
gunzip -c $(ls -t ~/backups/finance_*.sql.gz | head -1) | docker compose exec -T db psql -U postgres -d restore_test -q
docker compose exec -T db psql -U postgres -d restore_test -c "SELECT count(*) FROM category;"
docker compose exec -T db psql -U postgres -c "DROP DATABASE restore_test;"
```

Дампы лежат на том же сервере, что и база: если удалить или пересоздать виртуальную машину, они пропадут вместе с ней. Время от времени копируйте папку к себе (`scp -r user@сервер:~/backups .`) или включите бэкап всей ВМ в Proxmox.

### Локально для разработки

База в Docker, бот на твоём компьютере.

1. Клонируй репозиторий и перейди в папку проекта:
   ```
   git clone <адрес-репозитория>
   cd finance-app
   ```

2. Создай виртуальное окружение и установи зависимости:
   ```
   python -m venv venv
   .\venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   ```
   В Linux и macOS активация: `source venv/bin/activate`.

3. Создай файл `.env` по образцу `.env.example` и заполни его:
   ```
   BOT_TOKEN=токен_от_BotFather
   DB_PASSWORD=придуманный_пароль_для_базы
   ```

4. Запусти только базу данных (без контейнера бота):
   ```
   docker compose up -d db
   ```

5. Примени миграции (и повторяй после каждого `git pull`, если в `alembic/versions` появились новые файлы):
   ```
   alembic upgrade head
   ```
   Миграция `add non-negative balance check` не применится, если в базе уже есть наличные или крипта с отрицательным балансом — такие балансы нужно сначала исправить.

6. Заполни стандартные категории:
   ```
   python -m scripts.seed_categories
   ```

7. Запусти бота:
   ```
   python -m app.bot.main
   ```

## Тесты

Тесты работают с отдельной базой `finance_test`: перед каждым тестом в ней создаются таблицы, после — всё удаляется. Рабочие данные бота не затрагиваются.

1. Установи зависимости для разработки:
   ```
   pip install -r requirements-dev.txt
   ```

2. Один раз создай тестовую базу (контейнер с PostgreSQL должен быть запущен):
   ```
   docker compose exec db psql -U postgres -c "CREATE DATABASE finance_test;"
   ```

3. Запусти тесты:
   ```
   pytest -v
   ```

Что покрыто тестами:
- разбор суммы и записи (`кофе 5`, `5 кофе`, `+500 зарплата`), дата в тексте (`вчера кофе 5`, `05.11`), проверка эмодзи
- обновление баланса и запрет минуса для наличных и крипты, овердрафт карты, `CHECK` в базе
- удаление операций: откат баланса, чужая и несуществующая запись, запрет удалить уже потраченный доход
- переводы: успех и все ошибки (чужой счёт, тот же счёт, разные валюты, сумма, нехватка денег)
- категории: доступ только к своим и общим, совпадение типа, дубли названий
- диалоги бота целиком: запись и подтверждение (`test_entry_flow.py`), первый запуск, `/feedback`, `/delete_my_data`
- быстрый ввод, вечерние сообщения и итог недели, воронка `/funnel`, подсказка категории (история и ИИ)
- правка суммы, описания и даты записанной операции с пересчётом баланса (`test_tx_edit_flow.py`)
- лимиты: пороги 80% и превышение, диалог `/limits`, удаление только своего лимита (`test_limits.py`)
- регулярные операции: расписание (31-е число, декабрь, каждые 30 дней, 29 февраля), диалоги всех периодов, правка суммы и даты, вопрос «Добавить?» один раз в день, двойное нажатие, пропуск, удаление данных (`test_recurring.py`)
- периоды и тексты `/stats`, общий баланс в `/accounts`

Часть диалогов (например, листание `/history`) тестами не покрыта и проверяется вручную в Telegram.

Проверка стиля кода:
```
ruff check --select I,F401 --fix
ruff format
```

## REST API (в разработке)

Минимальный API на FastAPI для будущего Telegram Mini App: получение, создание и удаление транзакций (`DELETE /transactions/{id}?account_id=...`). Если операция увела бы наличные или крипту в минус, API отвечает `409`.

⚠️ Авторизации пока нет: API нельзя открывать наружу.

```
uvicorn app.api.main:app --reload
```

Документация открывается по адресу http://127.0.0.1:8000/docs.

## Переменные окружения

| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | Токен бота, который выдаёт [@BotFather](https://t.me/BotFather) |
| `DB_PASSWORD` | Пароль пользователя `postgres` в базе данных |
| `DB_HOST` | Адрес базы. Необязательная: по умолчанию `localhost`, в Docker Compose всегда `db` (Compose перекрывает значение из `.env`) |
| `GROQ_API_KEY` | Необязательная. Ключ Groq для подсказки категории ИИ. Без него ИИ отключён |
| `GROQ_MODEL` | Необязательная. Модель Groq, по умолчанию `openai/gpt-oss-20b` |
| `ADMIN_CHAT_ID` | Необязательная. Telegram id чата автора: туда бот пересылает отзывы из `/feedback`, и только там работает `/funnel`. Без неё `/feedback` отвечает, что приём отзывов выключен, а `/funnel` не работает ни у кого |

### Приватность при включённом ИИ
Если по истории категорию угадать не удалось, в Groq (сторонний сервис) уходят **только описание траты** (например, «шаурма») и **названия категорий** пользователя. Суммы, счета, Telegram id и имена не отправляются. Чтобы отключить ИИ полностью, уберите `GROQ_API_KEY`. Ключ хранится только в `.env` и не должен попадать в git.

### Отзывы (`/feedback`)
Человек пишет отзыв одним сообщением (до 1000 символов), выбирает «с моим именем» (автор видит имя, `@username` и id и может ответить) или «анонимно» (ни id, ни имени), и бот пересылает его в чат `ADMIN_CHAT_ID`. **Бот отзывы не хранит**: после пересылки они лежат только в переписке автора, поэтому их нельзя удалить командой `/delete_my_data` (бот об этом предупреждает). Защита от спама: не чаще одного отзыва в минуту на человека (счётчик в памяти и сбрасывается при перезапуске бота); лимит «бронируется» до отправки, поэтому два одновременных нажатия не отправят отзыв дважды. Текст и имя экранируются, если отправка автору не удалась, человек получает сообщение и может сразу попробовать снова. Узнать свой chat id можно, например, у `@userinfobot`; для группы id отрицательный.

### Удаление данных пользователя
Командой `/delete_my_data` человек сам удаляет всё, что бот о нём хранит: счета, операции, переводы, свои категории и профиль. Перед удалением бот показывает, сколько чего будет удалено, и просит подтвердить; удаление необратимо и выполняется одной транзакцией (либо удаляется всё, либо ничего). Общие категории не затрагиваются. Из ежедневных дампов базы на сервере записи пропадают по мере их ротации (срок в `BACKUP_RETENTION_DAYS`, сейчас 14 дней); если изменить срок хранения дампов в cron, нужно поменять и эту константу.

### Первый запуск
При первом `/start` бот спрашивает только валюту (BYN, RUB, USD, EUR) и сразу создаёт активный счёт «Карта» с типом card и балансом 0. Тип card выбран специально: карта может уйти в минус, поэтому первая трата не упадёт с «не хватает денег». Под сообщением кнопки «Название», «Тип» и «Остаток». Остаток можно указать только пока на счёте нет операций и переводов, иначе баланс разойдётся с историей. Двойное нажатие на валюту не создаст два счёта: строка пользователя блокируется до конца транзакции (`create_first_account`). Второй и следующие счета создаются по-старому через `/create_account`.

После 20-й записи (`QUICK_ENTRY_OFFER_AFTER`) бот один раз предлагает включить быстрый ввод тем, у кого он выключен.

### Быстрый ввод и вечернее сообщение (`/settings`)
**Быстрый ввод** (по умолчанию выключен): трата сохраняется сразу, без окна подтверждения, а под ответом есть кнопка «✏️ Изменить» (сменить категорию или удалить). Если категорию угадали по истории, запись считается проверенной. Если её предложил ИИ или не угадали вовсе (тогда трата попадает в «Другое»), у операции ставится флаг `needs_review`. Если категории «Другое» нужного типа нет (например, на новой базе до `seed_categories`), бот спрашивает категорию как обычно. Сумма, похожая на опечатку, всё равно идёт через окно подтверждения: больше средней по категории в `QUICK_UNUSUAL_FACTOR` раз, а без истории — больше `QUICK_MAX_WITHOUT_HISTORY`.

**Вечернее сообщение** (по умолчанию включено) приходит в 20:00 по Минску всем, у кого есть счёт. Если есть траты с `needs_review`, это список «проверь» с кнопками, иначе — короткое напоминание записать траты. Выключается в `/settings` или кнопкой «Не напоминать». Если человек заблокировал бота, напоминания ему выключаются автоматически. Планировщик — фоновая задача внутри процесса бота (`app/services/reminders.py`); если бот перезапущен после 20:00, сообщение за этот день пропускается.

### Итог недели и первая запись
По воскресеньям в 20:00 вместо напоминания приходит итог недели (понедельник–воскресенье по Минску): сколько потрачено и на сколько трат, главная категория и ещё две (`WEEKLY_TOP_CATEGORIES`), сумма прошлой недели. Каждая валюта считается отдельно. Доходы в итог не входят. Если за неделю трат не было, приходит обычное напоминание; траты на проверку добавляются под итогом. После самой первой записи бот обещает этот итог (только если вечерние сообщения включены).

### Воронка (`/funnel`, только для автора)
В `users.created_at` хранится дата регистрации (у пришедших до появления колонки — пусто). Команда `/funnel` работает только в чате `ADMIN_CHAT_ID`, остальным бот отвечает как на незнакомую команду. Показывает за последние 14 дней (`FUNNEL_DAYS`) по дням регистрации: сколько пришли, создали счёт, сделали первую трату и вторую+, и итог по всем пользователям. Связать ролик с притоком можно по дате публикации.

## Структура проекта

```
finance-app/
├── alembic/              миграции базы данных
├── app/
│   ├── api/              REST API: точка входа, роутер, Pydantic-схемы
│   ├── bot/
│   │   ├── handlers/     обработчики: start, help, transaction, add_category, history,
│   │   │                 stats, accounts, account_edit (правка счёта кнопками), transfer,
│   │   │                 delete_data, feedback, settings, admin (/funnel),
│   │   │                 review (карточка операции: проверить, категория, удалить),
│   │   │                 tx_edit (правка суммы, описания, даты), limits, recurring, cancel
│   │   ├── entry.py      окно подтверждения записи: текст, клавиатуры, смена даты
│   │   ├── states.py     состояния диалогов (FSM)
│   │   ├── texts.py      общие тексты сообщений и подписи счетов
│   │   └── main.py       точка входа бота, порядок роутеров и меню команд
│   ├── models/           таблицы: User, Account, Category, Transaction, Transfer,
│   │                     CategoryLimit, RecurringPayment
│   ├── repositories/     вся работа с базой данных
│   ├── services/         ai_categorizer.py (подсказка категории через Groq),
│   │                     reminders.py (вечернее сообщение и итог недели),
│   │                     limits.py (прогресс и предупреждения по лимитам),
│   │                     recurring.py (расписание и вопрос «Добавить?» в 20:00)
│   ├── constants.py      валюты, типы счетов (и какие могут уйти в минус), размер страницы,
│   │                     пороги быстрого ввода, время напоминаний, срок хранения бэкапов
│   ├── database.py       подключение к PostgreSQL
│   ├── exceptions.py     ошибки переводов, нехватки денег и правки остатка счёта
│   └── parsing.py        разбор суммы и записи «описание сумма», проверка эмодзи
├── scripts/
│   ├── seed_categories.py   стартовые категории
│   └── backup.sh            ежедневный дамп базы для cron
├── tests/                тесты pytest: репозитории, диалоги бота (test_*_flow.py),
│                         фикстуры тестовой базы (conftest.py)
├── Dockerfile            образ бота: ставит зависимости, при старте применяет миграции
├── docker-compose.yml    PostgreSQL + volume для данных и сервис бота
├── .env.example          образец файла с секретами (сам .env в git не попадает)
├── requirements.txt      зависимости приложения
└── requirements-dev.txt  зависимости для разработки: pytest, ruff
```

Проект разделён на слои: обработчики бота и API не пишут SQL, а обращаются к репозиториям, которые работают с моделями. Репозитории делают только `flush`, а `commit` — обработчик, поэтому изменение баланса и запись операции сохраняются вместе или не сохраняются вовсе.
