# Finance Bot

Telegram-бот для учёта личных финансов. Пишешь «кофе 5», выбираешь категорию — бот записывает расход и показывает остаток на счёте. Доход пишется с плюсом: «+500 зарплата». Есть несколько счетов, переводы между ними, история и статистика за месяц.

## Возможности

- Несколько счетов: 💳 карта, 💵 наличные, 🪙 криптовалюта; переключение активного счёта
- Валюты: USD, EUR, RUB, BYN
- Запись одним сообщением: `кофе 5`. По умолчанию — расход за сегодня
- Доход со знаком плюс: `+500 зарплата` или `зарплата +500`
- Категория угадывается по истории: если пользователь уже записывал «кофе» в «Еду», бот предложит её сам (регистр и пробелы не важны, учитываются все счета пользователя). Если не угадал, предлагает выбрать
- Если по истории не угадать, категорию предлагает ИИ ([Groq](https://console.groq.com), модель `openai/gpt-oss-20b`). В окне подтверждения такая категория помечена «🤖 предложил ИИ, проверь её», и её можно сменить. Нужен бесплатный ключ `GROQ_API_KEY`; без него бот работает как раньше, просто без ИИ
- Окно подтверждения со всеми данными (сумма, категория, счёт, дата) и кнопками «✅ Подтвердить», «📅 Сменить дату», «🏷 Сменить категорию», «❌ Отмена». Дата: «Вчера», «Сегодня» или `дд.мм.гггг` (будущие даты не принимаются)
- После подтверждения видны счёт и остаток; ошибочную запись можно удалить через `/history`
- Переводы между своими счетами одной валюты с подтверждением; повторное нажатие «Да» не выполнит перевод дважды
- Баланс наличных и крипты не может уйти в минус; карта может (овердрафт), бот предупреждает об этом
- Готовые категории и свои категории с эмодзи; дубли вроде «Еда» и «🍔 Еда» не создаются
- Статистика за любой месяц: расходы по категориям, доходы и разница
- История операций с постраничным просмотром (по 10 записей) и удалением с подтверждением
- Проверка введённой суммы: запятая, ноль, отрицательные, слишком большие и `nan`/`inf`
- `/help` с подсказками и ответ на неизвестные команды

### Надёжность и безопасность

- Проверка остатка и изменение баланса выполняются одним `UPDATE` в базе, поэтому параллельные операции не потратят одни и те же деньги
- Дополнительно в таблице `accounts` есть `CHECK`-ограничение: даже в обход кода база не сохранит минус на наличных или крипте
- Данным из кнопок не доверяем: счёт и категория всегда проверяются на владельца
- Текст, введённый пользователем, экранируется перед выводом, поэтому символы вроде `<` и `&` не ломают сообщения
- Ответу ИИ не доверяем: подходит только id категории из списка, который мы отправили (и только категории этого пользователя нужного типа); ошибка, таймаут (4 с) или неуверенность модели просто показывают обычный выбор категории. Бот не падает, если Groq недоступен
- Стикеры и фото вместо текста в диалогах не ломают бота
- Отмена любого действия через `/cancel` или кнопку «Отмена»

## Команды бота

| Команда | Что делает |
|---|---|
| `кофе 5` | Записать расход |
| `+500 зарплата` | Записать доход |
| `/history` | Последние операции с листанием и удалением |
| `/stats` | Расходы по категориям, доходы и разница за текущий месяц |
| `/stats мм.гггг` | То же за конкретный месяц, например `/stats 09.2026` |
| `/accounts` | Счета, балансы и переключение активного счёта |
| `/transfer` | Перевод с активного счёта на другой своей валюты |
| `/add_category` | Добавить свою категорию |
| `/create_account` | Создать новый счёт |
| `/help` | Как пользоваться ботом |
| `/settings` | Быстрый ввод без подтверждения и вечернее напоминание в 20:00 |
| `/feedback` | Написать автору отзыв, идею или сообщить об ошибке (можно анонимно) |
| `/delete_my_data` | Удалить все свои данные (счета, операции, переводы, свои категории, профиль) после подтверждения |
| `/cancel` | Отменить текущее действие |
| `/start` | Регистрация и создание первого счёта |

### Как удалить операцию

1. Открой `/history` — у каждой записи есть номер и кнопка `🗑`.
2. Нажми `🗑` нужного номера — бот покажет операцию и спросит подтверждение.
3. «✅ Да, удалить» удаляет запись и возвращает тебя на ту же страницу истории, «Отмена» — просто возвращает.

## Стек

- Python (разработка велась на 3.14)
- [aiogram](https://docs.aiogram.dev/) 3 — Telegram-бот
- SQLAlchemy 2 (async) + asyncpg — работа с базой
- PostgreSQL в Docker
- Alembic — миграции
- FastAPI — REST API (в разработке)
- pytest + pytest-asyncio — тесты
- ruff — линтер и форматирование
- python-dotenv — переменные окружения

## Запуск

1. Клонируй репозиторий и перейди в папку проекта:
   ```
   git clone <адрес-репозитория>
   cd finance-app
   ```

2. Создай виртуальное окружение и установи зависимости:
   ```
   python -m venv venv
   .\venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   ```
   В Linux и macOS активация: `source venv/bin/activate`.

3. Создай файл `.env` по образцу `.env.example` и заполни его:
   ```
   BOT_TOKEN=токен_от_BotFather
   DB_PASSWORD=придуманный_пароль_для_базы
   ```

4. Запусти базу данных:
   ```
   docker compose up -d
   ```

5. Примени миграции (и повторяй после каждого `git pull`, если в `alembic/versions` появились новые файлы):
   ```
   alembic upgrade head
   ```
   Миграция `add non-negative balance check` не применится, если в базе уже есть наличные или крипта с отрицательным балансом — такие балансы нужно сначала исправить.

6. Заполни стандартные категории:
   ```
   python -m scripts.seed_categories
   ```

7. Запусти бота:
   ```
   python -m app.bot.main
   ```

## Тесты

Тесты работают с отдельной базой `finance_test`: перед каждым тестом в ней создаются таблицы, после — всё удаляется. Рабочие данные бота не затрагиваются.

1. Установи зависимости для разработки:
   ```
   pip install -r requirements-dev.txt
   ```

2. Один раз создай тестовую базу (контейнер с PostgreSQL должен быть запущен):
   ```
   docker compose exec db psql -U postgres -c "CREATE DATABASE finance_test;"
   ```

3. Запусти тесты:
   ```
   pytest -v
   ```

Что покрыто тестами:
- разбор суммы и записи (`кофе 5`, `+500 зарплата`), проверка эмодзи
- обновление баланса и запрет минуса для наличных и крипты, овердрафт карты, `CHECK` в базе
- удаление операций: откат баланса, чужая и несуществующая запись, запрет удалить уже потраченный доход
- переводы: успех и все ошибки (чужой счёт, тот же счёт, разные валюты, сумма, нехватка денег)
- категории: доступ только к своим и общим, совпадение типа, дубли названий

Хендлеры бота тестами не покрыты — диалоги проверяются вручную в Telegram.

Проверка стиля кода:
```
ruff check --select I,F401 --fix
ruff format
```

## REST API (в разработке)

Минимальный API на FastAPI для будущего Telegram Mini App: получение, создание и удаление транзакций (`DELETE /transactions/{id}?account_id=...`). Если операция увела бы наличные или крипту в минус, API отвечает `409`.

⚠️ Авторизации пока нет: API нельзя открывать наружу.

```
uvicorn app.api.main:app --reload
```

Документация открывается по адресу http://127.0.0.1:8000/docs.

## Переменные окружения

| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | Токен бота, который выдаёт [@BotFather](https://t.me/BotFather) |
| `DB_PASSWORD` | Пароль пользователя `postgres` в базе данных |
| `DB_HOST` | Адрес базы. Необязательная: по умолчанию `localhost`, в Docker Compose — `db` |
| `GROQ_API_KEY` | Необязательная. Ключ Groq для подсказки категории ИИ. Без него ИИ отключён |
| `GROQ_MODEL` | Необязательная. Модель Groq, по умолчанию `openai/gpt-oss-20b` |
| `ADMIN_CHAT_ID` | Необязательная. Telegram id чата, куда бот пересылает отзывы из `/feedback`. Без неё команда отвечает, что приём отзывов выключен |

### Приватность при включённом ИИ
Если по истории категорию угадать не удалось, в Groq (сторонний сервис) уходят **только описание траты** (например, «шаурма») и **названия категорий** пользователя. Суммы, счета, Telegram id и имена не отправляются. Чтобы отключить ИИ полностью, уберите `GROQ_API_KEY`. Ключ хранится только в `.env` и не должен попадать в git.

### Отзывы (`/feedback`)
Человек пишет отзыв одним сообщением (до 1000 символов), выбирает «с моим именем» (автор видит имя, `@username` и id и может ответить) или «анонимно» (ни id, ни имени), и бот пересылает его в чат `ADMIN_CHAT_ID`. **Бот отзывы не хранит**: после пересылки они лежат только в переписке автора, поэтому их нельзя удалить командой `/delete_my_data` (бот об этом предупреждает). Защита от спама: не чаще одного отзыва в минуту на человека (счётчик в памяти и сбрасывается при перезапуске бота); лимит «бронируется» до отправки, поэтому два одновременных нажатия не отправят отзыв дважды. Текст и имя экранируются, если отправка автору не удалась, человек получает сообщение и может сразу попробовать снова. Узнать свой chat id можно, например, у `@userinfobot`; для группы id отрицательный.

### Удаление данных пользователя
Командой `/delete_my_data` человек сам удаляет всё, что бот о нём хранит: счета, операции, переводы, свои категории и профиль. Перед удалением бот показывает, сколько чего будет удалено, и просит подтвердить; удаление необратимо и выполняется одной транзакцией (либо удаляется всё, либо ничего). Общие категории не затрагиваются. Из ежедневных дампов базы на сервере записи пропадают по мере их ротации (срок в `BACKUP_RETENTION_DAYS`, сейчас 14 дней); если изменить срок хранения дампов в cron, нужно поменять и эту константу.

### Первый запуск
При первом `/start` бот спрашивает только валюту (BYN, RUB, USD, EUR) и сразу создаёт активный счёт «Карта» с типом card и балансом 0. Тип card выбран специально: карта может уйти в минус, поэтому первая трата не упадёт с «не хватает денег». Под сообщением кнопки «Название», «Тип» и «Остаток». Остаток можно указать только пока на счёте нет операций и переводов, иначе баланс разойдётся с историей. Двойное нажатие на валюту не создаст два счёта: строка пользователя блокируется до конца транзакции (`create_first_account`). Второй и следующие счета создаются по-старому через `/create_account`.

После 20-й записи (`QUICK_ENTRY_OFFER_AFTER`) бот один раз предлагает включить быстрый ввод тем, у кого он выключен.

### Быстрый ввод и вечернее сообщение (`/settings`)
**Быстрый ввод** (по умолчанию выключен): трата сохраняется сразу, без окна подтверждения, а под ответом есть кнопка «✏️ Изменить» (сменить категорию или удалить). Если категорию угадали по истории, запись считается проверенной. Если её предложил ИИ или не угадали вовсе (тогда трата попадает в «Другое»), у операции ставится флаг `needs_review`. Сумма, похожая на опечатку, всё равно идёт через окно подтверждения: больше средней по категории в `QUICK_UNUSUAL_FACTOR` раз, а без истории — больше `QUICK_MAX_WITHOUT_HISTORY`.

**Вечернее сообщение** (по умолчанию включено) приходит в 20:00 по Минску всем, у кого есть счёт. Если есть траты с `needs_review`, это список «проверь» с кнопками, иначе — короткое напоминание записать траты. Выключается в `/settings` или кнопкой «Не напоминать». Если человек заблокировал бота, напоминания ему выключаются автоматически. Планировщик — фоновая задача внутри процесса бота (`app/services/reminders.py`); если бот перезапущен после 20:00, сообщение за этот день пропускается.

## Структура проекта

```
finance-app/
├── alembic/              миграции базы данных
├── app/
│   ├── api/              REST API: точка входа, роутер, Pydantic-схемы
│   ├── bot/
│   │   ├── handlers/     обработчики: start, help, transaction, add_category, history,
│   │   │                 stats, accounts, transfer, delete_data, feedback, settings,
│   │   │                 review (карточка операции: проверить, сменить категорию), cancel
│   │   ├── entry.py      окно подтверждения записи: текст, клавиатуры, смена даты
│   │   ├── states.py     состояния диалогов (FSM)
│   │   ├── texts.py      общие тексты сообщений и подписи счетов
│   │   └── main.py       точка входа бота, порядок роутеров и меню команд
│   ├── models/           таблицы: User, Account, Category, Transaction, Transfer
│   ├── repositories/     вся работа с базой данных
│   ├── services/         внешние сервисы: ai_categorizer.py (подсказка категории через Groq)
│   ├── constants.py      валюты, типы счетов (и какие могут уйти в минус), размер страницы
│   ├── database.py       подключение к PostgreSQL
│   ├── exceptions.py     ошибки переводов и нехватки денег
│   └── parsing.py        разбор суммы и записи «описание сумма», проверка эмодзи
├── scripts/
│   └── seed_categories.py   стартовые категории
├── tests/                тесты pytest, диалог записи целиком (test_entry_flow.py)
│                         и фикстуры тестовой базы (conftest.py)
├── docker-compose.yml    PostgreSQL + volume для данных
├── requirements.txt      зависимости приложения
└── requirements-dev.txt  зависимости для разработки: pytest, ruff
```

Проект разделён на слои: обработчики бота и API не пишут SQL, а обращаются к репозиториям, которые работают с моделями. Репозитории делают только `flush`, а `commit` — обработчик, поэтому изменение баланса и запись операции сохраняются вместе или не сохраняются вовсе.
